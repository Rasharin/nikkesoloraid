# 솔로레이드 보스 예약 수정 UI 설계

## 목표

마스터 계정의 마이페이지 > 보스 관리 > 예약된 레이드 관리에서 긴 보스 이름을 간결하게 표시하고, 예약 상태인 항목의 이름·설명·기간을 한 번에 수정할 수 있게 한다.

## 표시 규칙

- 예약 카드의 보스 이름은 15자까지 그대로 표시한다.
- 이름이 15자를 초과하면 앞 15자 뒤에 `...`을 붙인다.
- 축약된 이름에는 전체 이름을 확인할 수 있도록 `title` 속성을 제공한다.
- 축약은 예약 목록 표시에서만 적용하며 저장된 전체 이름은 변경하지 않는다.

## 수정 UI

- 기존 `기간 정정` 버튼 문구를 `수정`으로 변경한다.
- `수정`을 누르면 현재 카드 아래에 다음 입력란을 인라인으로 펼친다.
  - 보스 이름
  - 보스 설명
  - 시작 시각
  - 종료 시각
- 입력란은 예약에 저장된 현재 값으로 초기화한다.
- `저장`을 누르면 네 값을 하나의 수정 요청으로 저장한다.
- 기존 `취소` 동작은 수정 입력란을 닫고 변경 중인 값을 버린다.
- 예약 상태(`scheduled`)인 항목만 수정할 수 있다는 기존 제한을 유지한다.

## 데이터 처리

- 클라이언트 수정 payload에 `title`, `description`, `startsAtInput`, `endsAtInput`을 포함한다.
- PATCH API는 입력값을 검증한 뒤 `raid_label`, `description`, `starts_at`, `ends_at`, `updated_at`을 함께 갱신한다.
- 이름은 앞뒤 공백을 제거하며 빈 이름은 거부한다.
- 설명은 앞뒤 공백을 제거하고 빈 문자열을 허용한다.
- 예약의 내부 식별자인 `raid_key`와 기존 `image_path`는 변경하지 않는다. 이에 따라 연결된 데이터의 식별 안정성을 유지한다.
- 저장 성공 후 예약 목록을 다시 불러와 화면에 최신 값을 반영한다.

## 오류 처리

- 이름이 비어 있거나 기간이 유효하지 않으면 기존 토스트 방식으로 사용자에게 알리고 요청을 보내지 않는다.
- 서버에서도 동일하게 이름과 기간을 검증한다.
- 서버 저장 실패 시 기존 오류 처리 흐름을 유지하고 수정 입력 상태를 보존해 재시도할 수 있게 한다.

## 검증

- 15자 이하 이름은 원문 그대로, 16자 이상 이름은 앞 15자와 `...`으로 표시되는지 테스트한다.
- 수정 요청에 이름·설명·시작·종료 값이 모두 포함되고 서버 갱신 필드로 전달되는지 테스트한다.
- 이름 누락과 잘못된 기간이 거부되는지 확인한다.
- 관련 자동 테스트, ESLint, 프로덕션 빌드를 실행한다.
- 실행 중인 앱에서 긴 이름 표시와 인라인 수정 입력란을 모바일·데스크톱 폭으로 확인한다.

## 범위 제외

- 예약 이미지 수정
- `raid_key` 변경
- 진행 중이거나 완료·취소된 예약의 이름과 설명 수정
